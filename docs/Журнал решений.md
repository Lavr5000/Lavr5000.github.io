## 2026-06-16 — Миграция реестра: добавлено поле `categories` (one-time migration-исключение)

**Контекст:** редизайн лендинга (UPRD «Редизайн лендинга AI Vibes», фаза P5). Каталог получил фильтр по аудитории.

**Решение:** в `products.js` всем записям добавлено поле `categories: string[]`. Это **разовое исключение** из инварианта append-only (порядок и `id` записей не меняются; добавление нового ключа схемы — однократная санкционированная миграция, §0 п.8 UPRD).

**Enum категорий (канон):**
`estimators` (Сметчики) · `designers` (Проектировщики) · `construction-control` (Стройконтроль) · `pto` (ПТО) · `procurement` (Снабжение).

**Маппинг (best-fit, по UPRD P5):**
- `material-takeoff` → `["estimators","pto","procurement"]`
- `spec-reconciliation` → `["procurement","pto"]`
- `letters-claims` → `["pto"]` (visible=false)
- `voice-transcription` → `["construction-control"]`
- `works-cost-estimate` → `["estimators","pto"]`

Аудитория вне enum → `categories: []` (показывается только под чипом «Все»). Чип с 0 видимых записей (сейчас `designers`) рендерится как roadmap-состояние `aria-disabled`.

**Контракт CI:** `scripts/validate_products.mjs` ужесточён — каждая `visible!==false` запись ОБЯЗАНА иметь ключ `categories` (массив; `[]` допустимо; непустой — каждое значение из enum, иначе exit 1). Snapshot `.github/products-count.txt` не изменился (5).

**Следствие для скилла `stroysite-product-publish`:** при добавлении нового продукта скилл обязан спрашивать/писать `categories` (значения из enum). См. обновление скилла 2026-06-16.
